# 보안 기능 정의서

## 1. 개요

Electron 앱의 **프로세스 격리, 콘텐츠 보안 정책(CSP), IPC 노출 범위 통제, 개인정보 스크러빙, 배포 서명**을 다루는 기능입니다.

## 2. 목적 및 사용자 가치

- 렌더러에서 실행되는 코드가 시스템 자원에 직접 접근하지 못하도록 차단한다.
- 외부 스크립트 주입과 예기치 않은 네트워크 통신을 원천 차단한다.
- 오류 리포팅 과정에서 사용자 데이터가 유출되지 않게 한다.

## 3. 프로세스 격리

| 설정               | 값      | 목적                                             |
| ------------------ | ------- | ------------------------------------------------ |
| `contextIsolation` | `true`  | 렌더러와 preload의 실행 컨텍스트를 완전히 분리   |
| `nodeIntegration`  | `false` | 렌더러에서 Node.js API 직접 사용 금지            |
| `sandbox`          | `false` | preload에서 `contextBridge`를 사용하기 위해 필요 |

### 3.1 API 노출 방식

렌더러는 `window.api`와 `window.theme` 두 객체만 사용할 수 있으며, 두 객체는 preload에서 `contextBridge`로 **명시적으로 열거된 함수만** 노출한다.

| 노출 그룹                          | 포함 기능                                       |
| ---------------------------------- | ----------------------------------------------- |
| `api.task`                         | 로그 생성·조회·수정·삭제·태그 연결              |
| `api.note`                         | 노트 조회·자동 저장, AI 회고 스트리밍·조회·삭제 |
| `api.tag`                          | 태그 CRUD                                       |
| `api.project`                      | 프로젝트 CRUD                                   |
| `api.weeklyReflection`             | 주간 회고 조회·저장                             |
| `api.taskType` / `api.taskSubtype` | 작업 유형·세부 유형 CRUD                        |
| `api.crashReport`                  | 오류 리포팅 설정·전송·온보딩                    |
| `api.user`                         | 플랜 정보·기능 플래그 조회                      |
| `api.analytics`                    | 이벤트·페이지뷰 전송                            |
| `api.events`                       | 딥링크·업데이트 이벤트 구독                     |
| `api.updater`                      | 업데이트 설치 (개발 모드에서만 시뮬레이션 추가) |
| `theme`                            | OS 테마 변경 구독                               |

- 파일 시스템, 자식 프로세스 실행, 임의 셸 명령 실행 API는 노출하지 않는다.
- 이벤트 구독 함수는 전달된 콜백이 함수가 아니면 아무 동작도 하지 않는 빈 해제 함수를 반환한다.
- 이벤트 콜백 실행 중 발생한 오류는 잡아서 경고 로그만 남기고 전파하지 않는다.

## 4. 콘텐츠 보안 정책 (CSP)

모든 응답 헤더에 CSP를 주입한다.

| 지시어                      | 프로덕션                          | 개발                                       |
| --------------------------- | --------------------------------- | ------------------------------------------ |
| `default-src`               | `'self'`                          | `'self'`                                   |
| `base-uri`                  | `'self'`                          | `'self'`                                   |
| `script-src`                | `'self'`                          | `'self' 'unsafe-inline' 'unsafe-eval'`     |
| `style-src`                 | `'self' 'unsafe-inline'`          | 동일                                       |
| `font-src`                  | `'self' data:`                    | 동일                                       |
| `img-src`                   | `'self' data: blob:`              | 동일                                       |
| `connect-src`               | `'self'` + Sentry 수집 엔드포인트 | 추가로 로컬 개발 서버(HTTP/WebSocket) 허용 |
| `frame-src`                 | `'none'`                          | 동일                                       |
| `object-src`                | `'none'`                          | 동일                                       |
| `form-action`               | `'self'`                          | 동일                                       |
| `frame-ancestors`           | `'none'`                          | 동일                                       |
| `upgrade-insecure-requests` | 적용                              | 미적용                                     |

### 4.1 적용 범위

| 모드     | 적용 대상 URL                           |
| -------- | --------------------------------------- |
| 프로덕션 | `https://*/*`, `file://*`               |
| 개발     | `http://*/*`, `https://*/*`, `file://*` |

- `chrome-extension://`, `devtools://` 는 필터에서 제외해 DevTools 확장이 정상 동작하도록 한다.
- CSP 설정 중 오류가 발생해도 앱 실행을 중단하지 않고 경고만 남긴다.

### 4.2 허용되는 외부 통신

| 대상                       | 용도               |
| -------------------------- | ------------------ |
| Sentry 수집 엔드포인트     | 크래시 리포트 전송 |
| (개발) 로컬 Vite 개발 서버 | HMR                |

> 사용 분석(Umami)은 렌더러가 아닌 **메인 프로세스**에서 전송하므로 CSP `connect-src`의 제약을 받지 않는다.

## 5. IPC 보안

| ID         | 규칙                                                                                                   |
| ---------- | ------------------------------------------------------------------------------------------------------ |
| SEC-IPC-01 | 모든 IPC 채널은 preload에 명시적으로 등록된 것만 호출 가능하다.                                        |
| SEC-IPC-02 | IPC 핸들러의 오류는 공통 래퍼가 잡아 직렬화하며, 스택 트레이스 원문이 렌더러로 그대로 넘어가지 않는다. |
| SEC-IPC-03 | IPC 오류를 크래시 리포트로 전송할 때 **모든 인자 값을 `[redacted]`로 치환**한다.                       |
| SEC-IPC-04 | 크래시 리포트 채널은 순환 리포팅을 막기 위해 공통 래퍼를 거치지 않는다.                                |
| SEC-IPC-05 | 개발 전용 채널(업데이트 시뮬레이션)은 개발 모드에서만 등록된다.                                        |

## 6. 개인정보 스크러빙

크래시 리포트 전송 직전에 적용되는 규칙은 [`crash-report`](../crash-report/spec.ko.md) 문서 6절에 정리되어 있다. 요약하면 다음과 같다.

- 기본 개인정보 수집 비활성화
- `file://` 요청 정보 제거
- 스택 프레임 절대 경로를 파일명만 남기고 제거
- 추가 데이터 중 `db` / `path` / `file` 키 삭제
- 사용자 정보는 익명 ID만 유지
- `file://` 포함 브레드크럼 제거
- 성능 추적 비활성화

## 7. 입력 검증

| 대상           | 검증                                                       |
| -------------- | ---------------------------------------------------------- |
| 노트 링크 URL  | URL 파싱에 성공해야만 링크로 변환한다.                     |
| 로그 세부 유형 | 지정하려는 세부 유형이 대상 작업 유형에 속하는지 확인한다. |
| 태그 연결      | 개수 제한(5개)과 중복 여부를 확인한다.                     |
| 이름 필드      | 정규화 후 유일성 제약으로 중복을 차단한다.                 |

## 8. 배포 보안

| 항목                   | 내용                                                                                                      |
| ---------------------- | --------------------------------------------------------------------------------------------------------- |
| 코드 서명 / 노터라이즈 | `main` 브랜치 배포 워크플로에서 Electron 앱을 서명·노터라이즈한다.                                        |
| entitlements           | macOS 권한 정의 파일을 별도 관리한다.                                                                     |
| 패키징 포함 범위       | 허용 목록 방식. 빌드 산출물, `package.json`, 프로덕션 환경 파일을 제외한 모든 항목을 패키지에서 배제한다. |
| 런타임 의존성          | 워크스페이스 전체가 아니라 앱의 런타임 의존성 그래프만 선별해 복사한다.                                   |
| 업데이트 배포          | CloudFront를 통해 HTTPS로 배포하며, 업데이트 피드는 JSON 형식이다.                                        |

### 8.1 환경 변수 취급

- 환경 변수는 여러 후보 경로에서 파일을 탐색해 로딩하며, 이미 설정된 값을 덮어쓰지 않는다.
- 필수 환경 변수가 없으면 **예외를 던지지 않고 경고 후 빈 문자열을 반환**한다. 모듈 로딩 시점의 예외가 오류 핸들러 등록 이전에 앱을 죽이는 것을 막기 위함이다.
- 패키징 여부는 실행 파일 경로에 asar 아카이브가 포함되어 있는지로 판단한다.

## 9. 관련 기능

- 오류 스크러빙 상세: [`crash-report`](../crash-report/spec.ko.md)
- 윈도우 및 preload 구성: [`app-shell`](../app-shell/spec.ko.md)
- 로컬 데이터 보관: [`data-storage`](../data-storage/spec.ko.md)

## 10. 현재 제한사항 및 향후 계획

- 데이터베이스 파일이 암호화되어 있지 않아, 기기 접근 권한이 있는 사람은 내용을 읽을 수 있다.
- 앱 잠금(비밀번호·생체 인증) 기능이 없다.
- 인증 체계가 없어 사용자별 접근 제어 개념이 존재하지 않는다.
- CSP에서 `style-src`에 인라인 스타일을 허용하고 있다(스타일링 방식상 필요).
- 개발 모드 CSP는 인라인·eval 스크립트를 허용하므로, 개발 빌드를 배포에 사용해서는 안 된다.
- 딥링크 인터페이스가 노출되어 있으나 처리 로직이 없어, 향후 구현 시 URL 검증 규칙을 함께 정의해야 한다.
