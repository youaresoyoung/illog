# 프로젝트 기능 정의서

## 1. 개요

로그(Task)를 묶는 상위 단위인 **프로젝트**를 관리하고 로그에 지정/해제하는 기능입니다. 프로젝트는 주간 요약 분석과 프로젝트 인사이트 화면의 1차 분류 축이 됩니다.

## 2. 목적 및 사용자 가치

- "무슨 일에 시간을 썼는가"를 프로젝트 단위로 집계할 수 있게 한다.
- 프로젝트별 진행률·소요 시간을 한눈에 확인할 근거 데이터를 만든다.

## 3. 용어 정의

| 용어              | 정의                                                          |
| ----------------- | ------------------------------------------------------------- |
| 프로젝트(Project) | 여러 로그를 묶는 상위 분류. 이름과 색상을 가진다              |
| 지정(Assign)      | 로그에 특정 프로젝트를 설정하는 행위                          |
| 미분류            | 프로젝트가 지정되지 않은 로그. 분석 화면에서 `etc`로 집계된다 |

## 4. 데이터 모델

테이블 `project` (`src/main/database/schema/project.ts`)

| 컬럼         | 타입      | 제약 / 기본값                                                               |
| ------------ | --------- | --------------------------------------------------------------------------- |
| `id`         | text      | PK, UUID 자동 생성                                                          |
| `name`       | text      | NOT NULL, UNIQUE 인덱스                                                     |
| `color`      | text enum | `blue` \| `green` \| `yellow` \| `purple` \| `red` \| `gray`, 기본값 `blue` |
| `created_at` | text      | NOT NULL, 기본값 현재 시각                                                  |
| `updated_at` | text      | NULL 허용                                                                   |
| `deleted_at` | text      | 소프트 삭제 시각                                                            |

관계: `project` 1 : N `task` — `task.project_id`는 `ON DELETE CASCADE`

## 5. 기능 상세

| ID        | 기능                   | 설명                                                            |
| --------- | ---------------------- | --------------------------------------------------------------- |
| FR-PRJ-01 | 프로젝트 생성          | 이름과 색상으로 프로젝트를 생성한다. 이름은 정규화 후 저장된다. |
| FR-PRJ-02 | 프로젝트 단건 조회     | ID로 프로젝트를 조회한다. 삭제된 프로젝트는 조회되지 않는다.    |
| FR-PRJ-03 | 프로젝트 전체 조회     | 삭제되지 않은 모든 프로젝트 목록을 반환한다.                    |
| FR-PRJ-04 | 프로젝트 수정          | 이름 또는 색상을 수정한다. 전달된 필드만 반영한다.              |
| FR-PRJ-05 | 프로젝트 삭제          | 소프트 삭제한다.                                                |
| FR-PRJ-06 | 로그에 프로젝트 지정   | 로그의 프로젝트를 설정한다.                                     |
| FR-PRJ-07 | 로그에서 프로젝트 해제 | 로그의 프로젝트를 비운다(미분류 상태).                          |

## 6. 비즈니스 규칙

| ID        | 규칙                                                                                                                                                                        |
| --------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| BR-PRJ-01 | 프로젝트 이름은 저장 전 정규화된다.                                                                                                                                         |
| BR-PRJ-02 | 이름은 전역에서 유일하다. 활성 상태의 동일 이름 프로젝트가 있으면 생성 시 오류를 반환한다.                                                                                  |
| BR-PRJ-03 | 삭제된 프로젝트와 같은 이름으로 생성하면 기존 레코드를 복구하며, 색상이 전달되지 않으면 `blue`로 설정된다.                                                                  |
| BR-PRJ-04 | 프로젝트 기본 색상은 `blue`다.                                                                                                                                              |
| BR-PRJ-05 | 로그는 프로젝트를 최대 1개 가진다.                                                                                                                                          |
| BR-PRJ-06 | 프로젝트가 삭제되어도 로그는 소프트 삭제만 사용하므로 실제 연쇄 삭제는 발생하지 않으며, 조회 시 삭제된 프로젝트가 조인에서 제외되어 로그 화면에서는 프로젝트가 비어 보인다. |
| BR-PRJ-07 | 프로젝트가 없는 로그는 분석 화면에서 `etc` 세그먼트로 집계된다.                                                                                                             |

## 7. 화면 및 인터랙션

### 7.1 로그에서의 프로젝트 지정 (`ProjectSection`)

로그 카드와 로그 상세 패널 양쪽에 배지 형태로 표시된다.

- 트리거: 지정된 프로젝트 배지. 없으면 `Add Project` 배지
- 드롭다운(`BadgeSelector`)
  - 검색 입력 (`Search projects...`)
  - 프로젝트 목록. 선택 시 지정, 해제 시 미분류
  - 목록에서 프로젝트 생성·수정·삭제 가능
- 지정/해제는 낙관적 업데이트로 처리한다.

### 7.2 프로젝트 목록 (`ProjectList`)

프로젝트 인사이트 화면(`/projects`)의 좌측 고정 사이드바(폭 256px).

- 항목마다 프로젝트 이름, 완료율 퍼센트, 완료율 막대(프로젝트 색상)를 표시한다.
- 선택된 프로젝트는 테두리 색으로 구분한다.
- 클릭 시 우측 인사이트 영역이 해당 프로젝트로 전환된다.

## 8. 예외 및 오류 처리

| 상황                                      | 처리                                        |
| ----------------------------------------- | ------------------------------------------- |
| 중복 이름으로 생성                        | `Project with name "<이름>" already exists` |
| 존재하지 않는 프로젝트 수정               | `Project not found or no changes made`      |
| 존재하지 않거나 이미 삭제된 프로젝트 삭제 | `Project not found`                         |

## 9. 인터페이스 (IPC 채널)

| 채널                 | 인자                      | 반환                       |
| -------------------- | ------------------------- | -------------------------- |
| `project.create`     | `{ name, color? }`        | 프로젝트                   |
| `project.get`        | `id`                      | 프로젝트 또는 빈 값        |
| `project.getAll`     | —                         | 프로젝트 목록              |
| `project.update`     | `id`, `{ name?, color? }` | 프로젝트                   |
| `project.softDelete` | `id`                      | —                          |
| `task.update`        | `id`, `{ projectId }`     | 로그 상세 (지정/해제 공용) |

## 10. 현재 제한사항 및 향후 계획

- 프로젝트 설명, 기간(시작/종료일), 상태(진행/보관) 같은 속성이 없다.
- 프로젝트 보관(archive) 개념이 없어 완료된 프로젝트도 목록에 계속 남는다.
- 프로젝트 정렬 순서를 사용자가 지정할 수 없다.
- 프로젝트 삭제 시 소속 로그를 어떻게 처리할지 사용자에게 묻지 않는다.
- `project_created`, `project_deleted` 분석 이벤트 상수는 정의되어 있으나 전송되지 않는다.
