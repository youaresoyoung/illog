# 오류 처리 기능 정의서

## 1. 개요

메인 프로세스에서 발생한 오류를 **유형이 보존된 형태로 렌더러까지 전달**하고, 사용자에게 이해 가능한 문구로 안내하는 체계입니다. 오류 분류, 프로세스 간 직렬화 프로토콜, 토스트 알림, 에러 바운더리를 포함합니다.

## 2. 목적 및 사용자 가치

- 내부 오류 메시지 대신 사용자가 이해할 수 있는 문구를 보여준다.
- 복구 가능한 오류와 그렇지 않은 오류를 구분해 재시도 여부를 결정한다.
- 프로세스 경계를 넘어도 오류 유형 정보가 사라지지 않게 한다.

## 3. 오류 코드 체계

| 오류 코드          | 사용자 문구                                                         | 분류 기준 (메시지 키워드)              |
| ------------------ | ------------------------------------------------------------------- | -------------------------------------- |
| `DB_ERROR`         | `Something went wrong while saving. Please try again.`              | `sqlite`, `database`, `constraint`     |
| `NOT_FOUND`        | `The requested item could not be found.`                            | `not found`, `no result`               |
| `VALIDATION_ERROR` | `Invalid input. Please check and try again.`                        | `invalid`, `required`, `validation`    |
| `AI_ERROR`         | `AI reflection is temporarily unavailable. Please try again later.` | `gemini`, `openai`, `ai reflection`    |
| `FEATURE_DISABLED` | `This feature requires a Pro plan.`                                 | `pro plan`, `feature is not available` |
| `UNKNOWN_ERROR`    | `An unexpected error occurred. Please try again.`                   | 위 어느 것에도 해당하지 않음           |

- `AppError` 인스턴스는 이미 코드를 가지고 있으므로 키워드 분류를 거치지 않는다.
- 키워드 판정은 **대소문자를 구분하지 않는다.**

## 4. 프로세스 간 오류 전달 프로토콜

Electron IPC는 오류 객체의 커스텀 속성을 그대로 전달하지 못하므로, 문자열 구분자를 이용한 자체 프로토콜을 사용한다.

```
[메인 프로세스]
  오류 발생
    → 오류 코드 분류
    → { __appError: true, message, code } 로 직렬화
    → `__APP_ERROR__` + JSON 문자열을 메시지로 하는 Error를 던짐
         ↓ IPC 경계
[preload]
  오류 메시지에서 `__APP_ERROR__` 구분자 위치 탐색
    → 뒤쪽 JSON 파싱
    → code 속성이 보존된 AppError 재구성 후 다시 던짐
         ↓
[렌더러]
  code 기반으로 재시도 여부 판단 + 사용자 문구 변환
```

| 규칙                                                                           |
| ------------------------------------------------------------------------------ |
| 구분자는 `__APP_ERROR__` 문자열이다.                                           |
| 구분자를 `indexOf`로 탐색하므로 오류 메시지에 어떤 문자가 포함되어도 안전하다. |
| 파싱에 실패하면 원본 오류를 그대로 다시 던진다.                                |
| 크래시 리포트 관련 IPC 채널은 이 래퍼를 거치지 않는다(순환 리포팅 방지).       |

## 5. 기능 상세

| ID        | 기능                 | 설명                                                            |
| --------- | -------------------- | --------------------------------------------------------------- |
| FR-ERR-01 | 오류 분류            | 오류 객체를 6개 코드 중 하나로 분류한다.                        |
| FR-ERR-02 | 오류 직렬화          | 메인 프로세스 오류를 구분자 기반 문자열로 직렬화한다.           |
| FR-ERR-03 | 오류 역직렬화        | preload에서 직렬화된 오류를 코드가 보존된 오류 객체로 복원한다. |
| FR-ERR-04 | 사용자 문구 변환     | 오류 코드에 대응하는 사용자 문구를 반환한다.                    |
| FR-ERR-05 | 전역 오류 토스트     | 데이터 변경 작업 실패 시 자동으로 오류 토스트를 표시한다.       |
| FR-ERR-06 | 전역 성공 토스트     | 성공 메시지가 지정된 작업이 성공하면 토스트를 표시한다.         |
| FR-ERR-07 | 조회 재시도 정책     | 오류 코드에 따라 재시도 여부를 결정한다.                        |
| FR-ERR-08 | 조회 오류 화면       | 화면 단위 조회 실패 시 안내 문구와 재시도 버튼을 표시한다.      |
| FR-ERR-09 | 렌더 에러 바운더리   | React 렌더 중 발생한 오류를 잡아 폴백 화면을 표시한다.          |
| FR-ERR-10 | IPC 오류 자동 리포팅 | 옵트인 상태이면 IPC 오류를 크래시 리포트로 전송한다.            |

## 6. 토스트 알림

| 항목           | 값                                               |
| -------------- | ------------------------------------------------ |
| 최대 표시 개수 | **3개**. 초과 시 가장 오래된 것부터 제거         |
| 중복 처리      | 메시지와 유형이 모두 같은 토스트는 추가하지 않음 |
| 유형           | `error`, `success`                               |
| ID             | 클라이언트에서 UUID로 생성                       |

### 6.1 메시지 조합 규칙

데이터 변경 작업에는 상황 설명 접두어를 붙일 수 있다.

| 설정        | 표시 문구                             |
| ----------- | ------------------------------------- |
| 접두어 없음 | `<오류 코드별 사용자 문구>`           |
| 접두어 있음 | `<접두어>: <오류 코드별 사용자 문구>` |
| 무음 설정   | 토스트를 표시하지 않음                |

예: 노트 저장 실패 시 → `Note failed to save: Something went wrong while saving. Please try again.`

## 7. 재시도 정책

| 대상                   | 정책                                                                                          |
| ---------------------- | --------------------------------------------------------------------------------------------- |
| 조회 (query)           | `NOT_FOUND`, `VALIDATION_ERROR`, `FEATURE_DISABLED`는 재시도하지 않음. 그 외는 **1회** 재시도 |
| 데이터 변경 (mutation) | 재시도하지 않음                                                                               |

### 7.1 조회 캐시 정책

| 항목                | 값        |
| ------------------- | --------- |
| 신선도 유지 시간    | 5분       |
| 캐시 보관 시간      | 30분      |
| 창 포커스 시 재조회 | 하지 않음 |

| 문구 | 오류 코드별 사용자 문구                        |

## 9. 비즈니스 규칙

| ID        | 규칙                                                                                                    |
| --------- | ------------------------------------------------------------------------------------------------------- |
| BR-ERR-01 | 사용자에게 내부 오류 메시지를 그대로 노출하지 않는다. 항상 오류 코드에 대응하는 문구로 변환한다.        |
| BR-ERR-02 | 오류 코드가 명확하지 않으면 `UNKNOWN_ERROR`로 처리한다.                                                 |
| BR-ERR-03 | 데이터 변경 작업의 오류 토스트는 전역 처리기가 담당하며, 개별 화면에서 중복으로 토스트를 띄우지 않는다. |
| BR-ERR-04 | 스트리밍처럼 데이터 변경 작업 형태가 아닌 경로는 직접 토스트를 호출한다.                                |
| BR-ERR-05 | 낙관적 업데이트가 적용된 작업은 실패 시 이전 상태로 롤백한 뒤 토스트를 표시한다.                        |
| BR-ERR-06 | IPC 오류를 크래시 리포트로 보낼 때 인자 값은 모두 가려서 전송한다.                                      |
| BR-ERR-07 | 오류 분류는 메시지 키워드 기반이므로, 메시지 문구가 바뀌면 분류 결과가 달라질 수 있다.                  |

## 11. 현재 제한사항 및 향후 계획

- 오류 분류가 **메시지 문자열 키워드 매칭**에 의존한다. 저장소 계층에서 명시적으로 `AppError`를 던지는 곳이 거의 없어, 대부분의 오류가 메시지 내용에 따라 사후 분류된다.
- 오류 문구가 영어로 하드코딩되어 있어 다국어를 지원하지 않는다.
- 오류 코드가 6개뿐이라 네트워크 오류·권한 오류 등 세분화된 상황을 구분하지 못한다.
- 사용자가 오류 상세 정보를 펼쳐 보거나 복사할 수단이 없다.
- 토스트 자동 사라짐 시간이 이 문서 범위(앱 코드) 밖의 공용 컴포넌트에 위임되어 있다.
