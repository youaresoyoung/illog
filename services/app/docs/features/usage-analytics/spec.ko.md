# 사용 분석(Usage Analytics) 기능 정의서

## 1. 개요

앱 사용 이벤트를 수집해 **Umami Cloud**로 전송하는 기능입니다. 별도 동의 항목을 두지 않고, 크래시 리포트 옵트인 설정을 그대로 따릅니다.

## 2. 목적 및 사용자 가치

- 어떤 기능이 실제로 사용되는지 파악해 제품 개선 우선순위를 정한다.
- 개인 식별 없이 집계 수준의 사용 패턴만 수집한다.

## 3. 용어 정의

| 용어                | 정의                                                         |
| ------------------- | ------------------------------------------------------------ |
| 이벤트(Event)       | 사용자 행동 1건을 나타내는 기록. 이름과 선택적 속성으로 구성 |
| 페이지뷰(Page View) | 화면 조회 기록                                               |
| 옵트인 연동         | 크래시 리포트 동의 여부를 그대로 사용 분석에도 적용하는 방식 |

## 4. 전송 대상 및 구성

| 항목              | 값                                                            |
| ----------------- | ------------------------------------------------------------- |
| 수집 서비스       | Umami Cloud                                                   |
| 기본 호스트       | `https://cloud.umami.is` (환경 변수 `UMAMI_HOST`로 변경 가능) |
| 사이트 ID         | 환경 변수 `UMAMI_WEBSITE_ID`                                  |
| 전송 방식         | HTTP 트래커(`@illog/analytics`의 `HttpTracker`)               |
| User-Agent        | `illog/<앱 버전> (<플랫폼>; <아키텍처>)`                      |
| 호스트명 컨텍스트 | `illog-electron`                                              |
| 언어              | 앱 로케일                                                     |
| 화면 해상도       | `0x0` (수집하지 않음)                                         |

## 5. 기능 상세

| ID       | 기능           | 설명                                                                           |
| -------- | -------------- | ------------------------------------------------------------------------------ |
| FR-UA-01 | 트래커 초기화  | 앱 시작 시 트래커를 생성하고 기본 컨텍스트를 설정한다.                         |
| FR-UA-02 | 옵트인 동기화  | 크래시 리포트 활성화 여부에 따라 트래커를 켜거나 끈다.                         |
| FR-UA-03 | 설정 변경 반영 | 사용자가 크래시 리포트 설정을 바꾸면 즉시 사용 분석 활성화 여부도 함께 바뀐다. |
| FR-UA-04 | 이벤트 전송    | 이름과 선택적 속성으로 이벤트를 전송한다.                                      |
| FR-UA-05 | 페이지뷰 전송  | URL과 선택적 제목으로 페이지뷰를 전송한다.                                     |
| FR-UA-06 | 종료 시 flush  | 앱 종료 전 전송 대기 중인 이벤트를 flush한다.                                  |

## 6. 실제 전송되는 이벤트

현재 코드에서 **실제로 전송이 이루어지는** 이벤트는 다음 4개다.

| 이벤트                 | 발생 시점               | 함께 전송되는 속성            |
| ---------------------- | ----------------------- | ----------------------------- |
| `app_launched`         | 앱 시작 시 1회          | `version`, `platform`, `arch` |
| `task_created`         | 로그 생성 성공 시       | 없음                          |
| `reflection_generated` | AI 회고 생성 완료 시    | 없음                          |
| `settings_opened`      | 설정 다이얼로그 열림 시 | 없음                          |
| `crash_report_toggled` | 오류 리포팅 토글 시     | `enabled`                     |

## 7. 정의되어 있으나 미사용인 이벤트

`@illog/analytics`에는 다음 이벤트 상수가 정의되어 있으나 데스크톱 앱에서 전송되지 않는다.

| 분류        | 이벤트                                                                                                              |
| ----------- | ------------------------------------------------------------------------------------------------------------------- |
| 앱 생명주기 | `app_updated`                                                                                                       |
| 내비게이션  | `page_viewed`, `tab_switched`                                                                                       |
| 로그        | `task_completed`, `task_deleted`, `task_time_started`, `task_time_stopped`                                          |
| 프로젝트    | `project_created`, `project_deleted`                                                                                |
| 태그        | `tag_created`, `tag_deleted`                                                                                        |
| 작업 유형   | `task_type_created`, `task_subtype_created`                                                                         |
| 노트 / 회고 | `note_auto_saved`, `reflection_deleted`                                                                             |
| 주간 회고   | `weekly_reflection_saved`                                                                                           |
| 설정        | `theme_changed`                                                                                                     |
| 필터        | `filter_applied`                                                                                                    |
| 웹 전용     | `download_clicked`, `header_nav_clicked`, `footer_link_clicked`, `feature_section_viewed`, `carousel_slide_changed` |

> 웹 전용 이벤트는 마케팅 사이트(`services/web`)용이며 데스크톱 앱과 무관하다.

## 8. 비즈니스 규칙

| ID       | 규칙                                                                                         |
| -------- | -------------------------------------------------------------------------------------------- |
| BR-UA-01 | 사용 분석은 **독립적인 동의 항목을 갖지 않는다.** 크래시 리포트 옵트인 상태를 그대로 따른다. |
| BR-UA-02 | 크래시 리포트가 비활성이면 트래커가 비활성화되어 어떤 이벤트도 전송되지 않는다.              |
| BR-UA-03 | 크래시 리포트 설정 변경 시 콜백을 통해 사용 분석 활성화 상태가 즉시 동기화된다.              |
| BR-UA-04 | 화면 해상도는 `0x0`으로 고정 전송되어 실제 값을 수집하지 않는다.                             |
| BR-UA-05 | 이벤트 속성 값은 문자열·숫자·불리언만 허용한다.                                              |
| BR-UA-06 | 앱 종료 시 트래커를 flush한 뒤 크래시 리포트 서비스를 종료한다.                              |

## 9. 인터페이스 (IPC 채널)

| 채널                 | 인자                 | 반환 |
| -------------------- | -------------------- | ---- |
| `analytics.track`    | `eventName`, `data?` | —    |
| `analytics.pageView` | `url`, `title?`      | —    |

렌더러에서는 `useAnalytics()` 훅(`trackEvent`, `trackPageView`) 또는 `window.api.analytics`를 통해 호출한다.

- 옵트인 설정: [`settings-onboarding`](../settings-onboarding/spec.ko.md)
- 옵트인 상태 소유: [`crash-report`](../crash-report/spec.ko.md)

## 11. 현재 제한사항 및 향후 계획

- **페이지뷰 트래킹이 모든 화면에서 비활성화되어 있다.** `usePageView` 훅은 구현되어 있으나 Today / This Week / History 화면에서 모두 TODO 주석으로 처리되어 호출되지 않는다.
- 정의된 이벤트 상수의 대부분이 실제로 전송되지 않는다(7절 참조).
- 사용 분석에 대한 독립적인 동의 항목이 없어, 크래시 리포트만 켜고 사용 분석은 끄는 선택이 불가능하다.
- 설정 화면의 수집 정보 안내에는 크래시 정보만 명시되어 있고 사용 분석 이벤트가 언급되지 않는다.
- 사용자가 자신의 전송 이력을 확인하거나 데이터 삭제를 요청할 경로가 없다.
- 이벤트 전송 실패 시 재시도 정책이 명시되어 있지 않다.
