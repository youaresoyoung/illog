# 자동 업데이트 기능 정의서

## 1. 개요

배포된 새 버전을 자동으로 확인·다운로드하고, 다운로드가 끝나면 사용자에게 **설치 여부를 묻는** 기능입니다. Electron 내장 업데이터(Squirrel)를 사용합니다.

## 2. 목적 및 사용자 가치

- 사용자가 직접 다운로드 페이지를 찾지 않아도 최신 버전을 유지할 수 있게 한다.
- 설치 시점은 사용자가 결정하도록 해 작업 중단을 막는다.

## 3. 업데이트 서버 구성

| 항목          | 값                                                                      |
| ------------- | ----------------------------------------------------------------------- |
| 업데이터      | Electron 내장 `autoUpdater`                                             |
| 서버 타입     | `json`                                                                  |
| 피드 URL 형식 | `https://<CLOUDFRONT_DOMAIN>/updates/<플랫폼>/<아키텍처>/RELEASES.json` |
| 배포 인프라   | CloudFront (환경 변수 `CLOUDFRONT_DOMAIN`)                              |

### 3.1 피드 URL 정규화 규칙

| 입력                                                  | 결과                                             |
| ----------------------------------------------------- | ------------------------------------------------ |
| 빈 문자열 또는 공백                                   | `null` (업데이터 비활성)                         |
| `.../RELEASES.json` 또는 `.../releases.json`으로 끝남 | 그대로 사용                                      |
| 그 외                                                 | 끝의 슬래시를 제거하고 `/RELEASES.json`을 덧붙임 |

## 4. 기능 상세

| ID       | 기능                      | 설명                                                              |
| -------- | ------------------------- | ----------------------------------------------------------------- |
| FR-UP-01 | 업데이터 초기화           | 피드 URL을 설정하고 업데이트 이벤트 리스너를 등록한다.            |
| FR-UP-02 | 업데이트 확인             | 메인 윈도우 표시 준비 완료 시 1회 업데이트를 확인한다.            |
| FR-UP-03 | 업데이트 가능 알림        | 새 버전이 있으면 렌더러에 알린다.                                 |
| FR-UP-04 | 다운로드 완료 알림        | 다운로드가 끝나면 릴리스 정보와 함께 렌더러에 알린다.             |
| FR-UP-05 | 업데이트 다이얼로그       | 다운로드 완료 시 설치 여부를 묻는 다이얼로그를 표시한다.          |
| FR-UP-06 | 즉시 설치                 | 앱을 종료하고 업데이트를 설치한다.                                |
| FR-UP-07 | 나중에 하기               | 다이얼로그를 닫고 현재 세션을 계속한다.                           |
| FR-UP-08 | Squirrel 설치 이벤트 처리 | Windows에서 설치·업데이트·제거 이벤트 발생 시 앱을 즉시 종료한다. |
| FR-UP-09 | 개발용 시뮬레이션         | 개발 모드에서 업데이트 다이얼로그를 테스트할 수 있게 한다.        |

### 4.1 업데이트 흐름

```
앱 시작
  → 피드 URL이 설정되어 있는지 확인
  → 업데이터 초기화 (개발 모드면 건너뜀)
  → 메인 윈도우 ready-to-show
      → checkForUpdates()
          → update-not-available : 아무 동작 없음
          → update-available     : 렌더러에 'update-available' 전송
              → 다운로드 (Squirrel이 자동 처리)
              → update-downloaded : 렌더러에 'update-downloaded' 전송
                  → 업데이트 다이얼로그 표시
                      → "Update Now"  → quitAndInstall()
                      → "Later"       → 다이얼로그 닫기
```

## 5. 화면 및 인터랙션

### 5.1 업데이트 다이얼로그 (`UpdateDialog`)

다운로드가 완료된 시점에만 표시된다.

| 요소        | 내용                                                               |
| ----------- | ------------------------------------------------------------------ |
| 접근성 라벨 | `Update Available`                                                 |
| 제목        | `Update Available`                                                 |
| 릴리스 이름 | 서버가 제공한 경우에만 표시                                        |
| 본문        | `A new version has been downloaded. Would you like to update now?` |
| 릴리스 노트 | 서버가 제공한 경우 원문 서식을 유지해 표시                         |
| 버튼        | `Update Now` (즉시 설치) / `Later` (닫기)                          |

- `update-available` 이벤트만으로는 다이얼로그를 표시하지 않는다. 다운로드 완료 시점에만 표시한다.

## 6. 비즈니스 규칙

| ID       | 규칙                                                                                  |
| -------- | ------------------------------------------------------------------------------------- |
| BR-UP-01 | 개발 모드에서는 업데이터를 초기화하지 않고 업데이트 확인도 건너뛴다.                  |
| BR-UP-02 | 피드 URL이 비어 있으면 업데이터를 비활성화하고 경고 로그만 남긴다.                    |
| BR-UP-03 | 업데이트 확인은 앱 실행 시 **1회**만 수행한다. 주기적 확인이 없다.                    |
| BR-UP-04 | 다운로드는 사용자에게 묻지 않고 자동으로 진행된다.                                    |
| BR-UP-05 | 설치는 반드시 사용자 확인을 거친다.                                                   |
| BR-UP-06 | `Later`를 선택하면 해당 세션에서는 다시 묻지 않는다.                                  |
| BR-UP-07 | Windows에서 Squirrel 설치 이벤트가 감지되면 앱을 즉시 종료한다.                       |
| BR-UP-08 | 업데이터 초기화·확인·설치 중 발생한 오류는 로그로만 남기고 앱 동작을 중단하지 않는다. |

## 7. 개발 모드 지원

| 항목             | 동작                                                                                                                                                                  |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 업데이터         | 초기화하지 않음                                                                                                                                                       |
| 업데이트 확인    | 건너뜀                                                                                                                                                                |
| `quitAndInstall` | 경고 로그만 남기고 동작하지 않음                                                                                                                                      |
| 시뮬레이션 채널  | `updater:simulateUpdate` — 개발 모드에서만 등록되며, 가상 릴리스(`Version 999.9.9 (Simulated)`) 정보로 다운로드 완료 이벤트를 발생시켜 다이얼로그를 테스트할 수 있다. |

시뮬레이션은 DevTools 콘솔에서 `window.api.updater.simulateUpdate()`로 호출할 수 있다.

## 8. 인터페이스

### 8.1 IPC 채널

| 채널                     | 방향          | 설명                               |
| ------------------------ | ------------- | ---------------------------------- |
| `updater:quitAndInstall` | 렌더러 → 메인 | 앱을 종료하고 업데이트를 설치      |
| `updater:simulateUpdate` | 렌더러 → 메인 | 개발 모드 전용 업데이트 시뮬레이션 |

### 8.2 메인 → 렌더러 이벤트

| 이벤트              | 페이로드                        | 설명             |
| ------------------- | ------------------------------- | ---------------- |
| `update-available`  | 없음                            | 새 버전이 확인됨 |
| `update-downloaded` | `{ releaseNotes, releaseName }` | 다운로드 완료    |

두 이벤트 모두 preload에서 구독 해제 함수를 반환하는 형태로 노출된다.

## 10. 현재 제한사항 및 향후 계획

- 주기적 업데이트 확인이 없어, 앱을 계속 켜 두면 실행 시점 이후의 새 버전을 감지하지 못한다.
- 사용자가 수동으로 "업데이트 확인"을 실행할 UI가 없다.
- 다운로드 진행률을 표시하지 않는다.
- `update-available` 이벤트를 받아도 렌더러에서 아무 UI도 표시하지 않는다(빈 콜백).
- 업데이트 실패를 사용자에게 알리지 않고 로그로만 남긴다.
- 업데이트 채널(stable/beta) 선택 기능이 없다.
- `app_updated` 분석 이벤트 상수는 정의되어 있으나 전송되지 않는다.
