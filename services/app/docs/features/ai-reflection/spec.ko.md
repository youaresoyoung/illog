# AI 회고 기능 정의서

## 1. 개요

작성된 노트 본문을 입력으로 받아 **AI가 회고 요약을 생성**하는 기능입니다. 생성 결과는 실시간 스트리밍으로 화면에 표시되고, 완료 시 로그에 1:1로 저장됩니다. 유료 플랜 전용 기능으로 게이팅되어 있습니다.

## 2. 목적 및 사용자 가치

- 길게 적은 작업 노트에서 핵심을 자동으로 뽑아내 회고 작성 부담을 줄인다.
- 생성 과정을 스트리밍으로 보여주어 대기 체감 시간을 줄인다.

## 3. 용어 정의

| 용어             | 정의                                                    |
| ---------------- | ------------------------------------------------------- |
| 회고(Reflection) | 노트 본문을 근거로 AI가 생성한 요약 텍스트              |
| TextRank         | 문장 간 유사도 그래프에서 중요 문장을 추출하는 알고리즘 |
| 스트리밍         | 생성된 텍스트를 조각(chunk) 단위로 순차 전달하는 방식   |

## 4. 데이터 모델

테이블 `task_reflection` (`src/main/database/schema/taskReflection.ts`)

| 컬럼                 | 타입 | 제약                                      |
| -------------------- | ---- | ----------------------------------------- |
| `id`                 | text | PK, UUID 자동 생성                        |
| `task_id`            | text | UNIQUE, `task.id` FK, `ON DELETE CASCADE` |
| `content`            | text | NOT NULL, 생성된 회고 본문                |
| `original_note_hash` | text | 입력 노트 본문의 SHA-256 해시             |
| `model_name`         | text | 생성에 사용된 모델 이름                   |
| `created_at`         | text | 생성 시각                                 |
| `updated_at`         | text | 수정 시각                                 |

- `task_id`가 UNIQUE이므로 로그당 회고는 **최대 1개**다.

## 5. 기능 상세

| ID        | 기능                | 설명                                                                                    |
| --------- | ------------------- | --------------------------------------------------------------------------------------- |
| FR-AIR-01 | 회고 생성(스트리밍) | 노트 본문을 입력으로 회고를 생성하며, 생성 중 텍스트 조각을 실시간으로 화면에 전달한다. |
| FR-AIR-02 | 핵심 문장 전처리    | 원문을 그대로 보내지 않고 TextRank로 핵심 문장만 추출해 입력으로 사용한다.              |
| FR-AIR-03 | 생성 결과 저장      | 스트리밍이 끝나면 전체 본문을 저장한다. 기존 회고가 있으면 덮어쓴다(upsert).            |
| FR-AIR-04 | 회고 조회           | 로그 ID로 저장된 회고를 조회한다.                                                       |
| FR-AIR-05 | 회고 삭제           | 로그 ID로 회고를 삭제한다.                                                              |
| FR-AIR-06 | 재생성 확인         | 기존 회고가 있는 상태에서 생성을 시도하면 덮어쓰기 확인 다이얼로그를 먼저 표시한다.     |
| FR-AIR-07 | 기능 게이팅         | 사용자 플랜에 `ai.reflection` 기능이 없으면 생성을 거부한다.                            |
| FR-AIR-08 | 리스너 해제         | 스트리밍 종료 후 이벤트 리스너를 제거한다.                                              |

### 5.1 처리 흐름

```
노트 본문
  → 문장 분리 (10자 미만 문장 제외)
  → 문장 간 유사도 행렬 계산
  → TextRank 점수 산출
  → 상위 문장 추출 후 원래 순서로 재조립
  → 프롬프트 템플릿에 결합
  → 생성 모델 호출 (스트리밍)
  → 청크 단위로 렌더러 전달
  → 완료 시 전체 본문 + 원문 해시 저장
```

### 5.2 TextRank 전처리 파라미터

| 항목                      | 값                                           |
| ------------------------- | -------------------------------------------- |
| 감쇠 계수(damping factor) | 0.85                                         |
| 반복 횟수                 | 30                                           |
| 최소 문장 길이            | 10자                                         |
| 추출 문장 수              | `max(3, 전체 문장 수의 30%)`                 |
| 예외                      | 전체 문장이 3개 이하면 전처리 없이 전량 사용 |

## 6. 비즈니스 규칙

| ID        | 규칙                                                                                                                        |
| --------- | --------------------------------------------------------------------------------------------------------------------------- |
| BR-AIR-01 | 로그당 회고는 최대 1개이며, 재생성 시 기존 회고를 덮어쓴다.                                                                 |
| BR-AIR-02 | 노트 본문이 비어 있으면 생성 버튼이 비활성화된다.                                                                           |
| BR-AIR-03 | 생성 중에는 버튼이 비활성화되고 라벨이 `Generating...`으로 바뀐다.                                                          |
| BR-AIR-04 | `ai.reflection` 기능이 비활성인 플랜에서는 버튼 라벨이 `AI Reflection (<필요 플랜> plan required)`로 표시되고 비활성화된다. |
| BR-AIR-05 | 기능 게이팅은 화면뿐 아니라 메인 프로세스에서도 재검증한다.                                                                 |
| BR-AIR-06 | 입력 텍스트가 비어 있거나 공백뿐이면 오류를 반환한다.                                                                       |
| BR-AIR-07 | 프롬프트 또는 모델 이름 환경 변수가 없으면 오류를 반환한다.                                                                 |
| BR-AIR-08 | 생성 시점의 노트 본문 해시를 함께 저장해 이후 원문 변경 여부를 판별할 수 있게 한다.                                         |
| BR-AIR-09 | 로그가 삭제되면 회고도 함께 삭제된다.                                                                                       |

## 7. 화면 및 인터랙션

위치: 로그 상세 패널(`RightPanel`) 최하단, 노트 에디터 아래

- 상단: `Ask AI Reflection` 버튼
- 하단: 회고 표시 영역(읽기 전용 에디터, 마크다운 렌더링, 최소 높이 240px)
- 빈 상태 문구: `No reflection generated yet...`
- 기존 회고가 있는 상태에서 버튼을 누르면 다이얼로그 표시
  - 제목: `Do you want to delete the previous summary?`
  - 설명: `To generate a new summary, the existing summary will be deleted.`
  - 버튼: `Cancel` / `Confirm`
- 생성이 진행되는 동안 스트리밍 텍스트가 표시 영역에 실시간으로 누적된다.
- 생성 완료 시 `reflection_generated` 분석 이벤트를 전송한다.

## 8. 예외 및 오류 처리

| 상황               | 처리                                                                                                               |
| ------------------ | ------------------------------------------------------------------------------------------------------------------ |
| 플랜에 기능이 없음 | `FEATURE_DISABLED` — "This feature requires a Pro plan."                                                           |
| 입력 텍스트 없음   | 오류 반환, 생성 중단                                                                                               |
| 환경 변수 누락     | 오류 반환, 생성 중단                                                                                               |
| 모델 호출 실패     | `AI_ERROR` — "AI reflection is temporarily unavailable. Please try again later."                                   |
| 스트리밍 중 오류   | 스트리밍 상태를 해제하고 오류 토스트를 표시한다. 이 경로는 React Query 뮤테이션이 아니므로 토스트를 직접 호출한다. |

## 9. 인터페이스 (IPC 채널)

| 채널                             | 방향          | 인자              | 설명                                         |
| -------------------------------- | ------------- | ----------------- | -------------------------------------------- |
| `note.reflectionNoteStream`      | 렌더러 → 메인 | `taskId`, `text`  | 생성 시작. 스트림이 끝날 때까지 대기         |
| `note.reflectionNoteStreamChunk` | 메인 → 렌더러 | `{ chunk, done }` | 생성된 텍스트 조각. `done: true`가 종료 신호 |
| `note.getReflection`             | 렌더러 → 메인 | `taskId`          | 저장된 회고 조회                             |
| `note.deleteReflection`          | 렌더러 → 메인 | `taskId`          | 회고 삭제                                    |
| `note.removeReflectionListener`  | 렌더러 → 메인 | —                 | 스트림 이벤트 리스너 해제                    |

## 10. 현재 제한사항 및 향후 계획

- **현재 API 키가 설정되어 있지 않아 실질적으로 동작하지 않는다.** `src/config/env.ts`의 `geminiApiKey`가 빈 문자열로 고정되어 있고 환경 변수 로딩이 주석 처리되어 있다.
- 기본 플랜이 `local`이므로 `ai.reflection` 기능은 모든 사용자에게 비활성 상태다.
- `original_note_hash`를 저장하지만, 노트가 변경되었을 때 "회고가 오래되었습니다"와 같은 안내를 하는 로직은 없다.
- `note.deleteReflection` IPC는 구현되어 있으나 화면에서 호출하는 진입점이 없다.
- 회고 결과를 사용자가 직접 편집하거나 재생성 없이 수정하는 기능이 없다.
- `ai.weekly-summary`, `ai.suggestion` 기능 플래그는 정의만 되어 있고 구현이 없다.
