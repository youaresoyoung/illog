# 크래시 리포트 기능 정의서

## 1. 개요

앱에서 발생한 오류를 **익명으로 수집해 Sentry로 전송**하는 기능입니다. 기본값은 비활성이며 사용자가 명시적으로 동의(옵트인)해야만 전송됩니다. 개인 식별 정보와 로컬 경로는 전송 전에 제거됩니다.

## 2. 목적 및 사용자 가치

- 사용자가 별도 제보 없이도 앱 안정성 개선에 기여할 수 있게 한다.
- 무엇이 전송되고 무엇이 전송되지 않는지 명확히 하여 프라이버시 우려를 낮춘다.

## 3. 용어 정의

| 용어                | 정의                                                              |
| ------------------- | ----------------------------------------------------------------- |
| 옵트인(Opt-in)      | 사용자가 명시적으로 동의해야 수집이 시작되는 방식                 |
| 익명 ID             | 사용자 식별용으로 무작위 생성되는 UUID. 개인 정보와 연결되지 않음 |
| 스크러빙(Scrubbing) | 전송 전에 민감 정보를 제거하는 처리                               |

## 4. 데이터 모델

`app_setting` 테이블에 키-값 형태로 저장된다.

| 키                     | 값            | 설명                     |
| ---------------------- | ------------- | ------------------------ |
| `crash_report_enabled` | `'0'` / `'1'` | 오류 리포팅 활성화 여부  |
| `anonymous_id`         | UUID 문자열   | 익명 사용자 식별자       |
| `onboarding_completed` | `'0'` / `'1'` | 첫 실행 온보딩 완료 여부 |

- `anonymous_id`는 설정을 **최초로 조회하는 시점에 자동 생성**되어 저장된다.
- 설정 조회 시 `crash_report_enabled` 값이 없으면 비활성으로 간주한다.

## 5. 기능 상세

| ID       | 기능                     | 설명                                                                         |
| -------- | ------------------------ | ---------------------------------------------------------------------------- |
| FR-CR-01 | Sentry 조기 초기화       | 앱 준비 이전 시점에 Sentry를 초기화한다. 전송 여부는 별도 플래그로 제어한다. |
| FR-CR-02 | 설정 적용                | 데이터베이스 연결 후 사용자 설정을 읽어 전송 활성화 여부를 결정한다.         |
| FR-CR-03 | 설정 조회                | 현재 활성화 여부와 익명 ID를 반환한다.                                       |
| FR-CR-04 | 설정 변경                | 활성화 여부를 변경하고 즉시 적용한다.                                        |
| FR-CR-05 | 수동 리포트 전송         | 렌더러에서 전달한 오류를 Sentry로 전송한다.                                  |
| FR-CR-06 | IPC 오류 자동 수집       | IPC 핸들러에서 발생한 오류를 채널 이름 태그와 함께 자동 전송한다.            |
| FR-CR-07 | 렌더러 전역 오류 처리    | 처리되지 않은 오류와 Promise 거부를 감지한다.                                |
| FR-CR-08 | 렌더 크래시 처리         | React 렌더 오류를 에러 바운더리로 잡아 폴백 화면을 표시한다.                 |
| FR-CR-09 | 크래시 리포트 다이얼로그 | 옵트인하지 않은 사용자에게 전송 여부를 묻는다.                               |
| FR-CR-10 | 온보딩 상태 관리         | 첫 실행 온보딩 완료 여부를 조회·기록한다.                                    |
| FR-CR-11 | 종료 시 flush            | 앱 종료 전 전송 대기 중인 이벤트를 최대 2초간 flush한다.                     |

### 5.1 오류 처리 경로

| 발생 위치                | 감지 방식                   | 옵트인 ON                  | 옵트인 OFF                         |
| ------------------------ | --------------------------- | -------------------------- | ---------------------------------- |
| 메인 프로세스 IPC 핸들러 | 공통 오류 래퍼              | 자동 전송 (채널 태그 포함) | 전송 안 함                         |
| 렌더러 전역 오류         | `window` `error` 이벤트     | 자동 전송                  | 크래시 다이얼로그 표시             |
| 렌더러 Promise 거부      | `unhandledrejection` 이벤트 | 자동 전송                  | 크래시 다이얼로그 표시             |
| React 렌더 오류          | 에러 바운더리               | 자동 전송                  | 크래시 다이얼로그 표시 + 폴백 화면 |

## 6. 개인정보 보호 규칙

Sentry 전송 직전(`beforeSend`)에 다음 처리가 적용된다.

| ID       | 규칙                                                                                |
| -------- | ----------------------------------------------------------------------------------- |
| PR-CR-01 | 전송 활성화 플래그가 꺼져 있으면 이벤트를 **폐기**한다.                             |
| PR-CR-02 | 릴리스 정보가 없는 이벤트는 폐기한다.                                               |
| PR-CR-03 | Sentry의 기본 개인정보 수집(`sendDefaultPii`)을 비활성화한다.                       |
| PR-CR-04 | 요청 URL이 `file://`로 시작하면 요청 정보 전체를 제거한다.                          |
| PR-CR-05 | 스택 프레임의 절대 경로를 **파일명만** 남기고 잘라내며, 절대 경로 필드를 삭제한다.  |
| PR-CR-06 | 추가 데이터(extra) 중 키 이름에 `db`, `path`, `file`이 포함된 항목을 모두 삭제한다. |
| PR-CR-07 | 사용자 정보는 익명 ID만 남기고 나머지를 제거한다.                                   |
| PR-CR-08 | 브레드크럼 중 `file://`을 포함하는 항목을 제거한다.                                 |
| PR-CR-09 | IPC 오류 전송 시 인자 값을 모두 `[redacted]`로 치환한다.                            |
| PR-CR-10 | 성능 추적(트레이싱)을 비활성화한다(샘플링 비율 0). 크래시 전용으로만 사용한다.      |
| PR-CR-11 | 브레드크럼 최대 개수를 50개로 제한한다.                                             |

### 6.1 함께 전송되는 태그

| 태그               | 값                                         |
| ------------------ | ------------------------------------------ |
| `arch`             | 프로세스 아키텍처                          |
| `electron_version` | Electron 버전                              |
| `os`               | 플랫폼                                     |
| `release`          | `<앱 이름>@<앱 버전>` (옵트인 시에만 설정) |
| `ipc_channel`      | IPC 오류인 경우 채널 이름                  |

## 7. 화면 및 인터랙션

### 7.1 크래시 리포트 다이얼로그 (`CrashReportDialog`)

옵트인하지 않은 상태에서 오류가 발생하면 표시된다.

| 요소           | 내용                                                                               |
| -------------- | ---------------------------------------------------------------------------------- |
| 역할           | `alertdialog`                                                                      |
| 제목           | `A crash has occurred`                                                             |
| 설명           | `Would you like to send an anonymous crash report to help improve the app?`        |
| 전송 정보 안내 | 앱 버전 및 운영체제 정보 / 크래시 위치(스택 트레이스) / 크래시 시각                |
| 고지           | `Personal identifiable information, local data, and file paths are not collected.` |
| 버튼           | `Don't send` / `Send report`                                                       |

`Send report`를 선택하면 해당 오류 1건만 전송되며, 설정 자체가 켜지지는 않는다.

### 7.2 렌더 크래시 폴백 화면 (`CrashErrorBoundary`)

| 요소 | 내용                                                                                        |
| ---- | ------------------------------------------------------------------------------------------- |
| 문구 | `Something went wrong` / `An unexpected error occurred. Please reload the app to continue.` |
| 버튼 | `Reload App` (창을 새로고침)                                                                |

## 8. 비즈니스 규칙

| ID       | 규칙                                                                                                                        |
| -------- | --------------------------------------------------------------------------------------------------------------------------- |
| BR-CR-01 | Sentry 초기화 자체는 항상 수행되지만, 전송 여부는 내부 플래그로 제어한다. Sentry는 앱 준비 이전에 초기화해야 하기 때문이다. |
| BR-CR-02 | 옵트인이 꺼져 있으면 어떤 이벤트도 전송되지 않는다.                                                                         |
| BR-CR-03 | 옵트인을 켜는 순간 릴리스 태그와 익명 사용자 ID가 설정된다.                                                                 |
| BR-CR-04 | 익명 ID는 최초 설정 조회 시 자동 생성되며, 옵트인 여부와 무관하게 생성된다.                                                 |
| BR-CR-05 | 개발 모드에서는 별도의 개발용 Sentry DSN을 사용하고 환경을 `development`로 설정한다.                                        |
| BR-CR-06 | 크래시 리포트 IPC 채널은 공통 오류 래퍼를 거치지 않는다(순환 리포팅 방지).                                                  |
| BR-CR-07 | 앱 종료 시 최대 2초 동안 전송 대기 이벤트를 flush한다.                                                                      |

## 11. 현재 제한사항 및 향후 계획

- 사용자가 자신의 오류 전송 이력을 확인할 수 없다.
- 오류 발생 시 사용자가 재현 절차 등 추가 설명을 덧붙일 수 없다.
- 크래시 다이얼로그에서 전송을 선택해도 다음 오류 때 다시 묻는다(기억하지 않음).
- 메인 프로세스 자체가 죽는 하드 크래시(네이티브 크래시)에 대한 별도 처리 경로가 없다.
- 오류 전송 실패 시 재시도·큐잉 정책이 없다.
