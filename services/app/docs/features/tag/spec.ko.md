# 태그 기능 정의서

## 1. 개요

로그(Task)에 자유롭게 붙일 수 있는 **태그**를 관리하고 로그에 연결/해제하는 기능입니다. 프로젝트·작업 유형이 정형 분류인 것과 달리, 태그는 사용자가 임의로 만드는 비정형 분류 수단입니다.

## 2. 목적 및 사용자 가치

- 정해진 분류 체계에 담기 어려운 맥락(예: `긴급`, `리팩터링`, `온보딩`)을 가볍게 표시한다.
- 로그당 개수를 제한해 태그가 무한정 늘어나 분류 기능을 잃는 것을 방지한다.

## 3. 용어 정의

| 용어          | 정의                                                                   |
| ------------- | ---------------------------------------------------------------------- |
| 태그(Tag)     | 이름과 색상을 가지는 라벨. 전역적으로 하나의 목록을 공유한다           |
| 연결          | 특정 로그에 태그를 붙이는 행위                                         |
| 복구(Restore) | 삭제된 태그와 같은 이름으로 다시 생성할 때 기존 레코드를 되살리는 동작 |

## 4. 데이터 모델

### 4.1 `tag` 테이블

| 컬럼         | 타입               | 제약 / 기본값                                                               |
| ------------ | ------------------ | --------------------------------------------------------------------------- |
| `id`         | text               | PK, UUID 자동 생성                                                          |
| `name`       | text               | NOT NULL, UNIQUE                                                            |
| `color`      | text enum          | `blue` \| `green` \| `yellow` \| `purple` \| `red` \| `gray`, 기본값 `gray` |
| `created_at` | integer(timestamp) | NOT NULL, 기본값 현재 시각                                                  |
| `updated_at` | integer(timestamp) | NOT NULL, 갱신 시 자동 변경                                                 |
| `deleted_at` | integer(timestamp) | 소프트 삭제 시각                                                            |

인덱스: `name`(UNIQUE), `deleted_at`

### 4.2 `task_tag` 조인 테이블

| 컬럼      | 타입 | 제약                              |
| --------- | ---- | --------------------------------- |
| `task_id` | text | `task.id` FK, `ON DELETE CASCADE` |
| `tag_id`  | text | `tag.id` FK, `ON DELETE CASCADE`  |

복합 기본 키 `(task_id, tag_id)` — 동일 조합의 중복 저장이 구조적으로 불가능하다.

## 5. 기능 상세

| ID        | 기능               | 설명                                                           |
| --------- | ------------------ | -------------------------------------------------------------- |
| FR-TAG-01 | 태그 생성          | 이름과 색상으로 태그를 생성한다. 이름은 정규화 후 저장된다.    |
| FR-TAG-02 | 태그 단건 조회     | ID로 태그를 조회한다. 삭제된 태그는 조회되지 않는다.           |
| FR-TAG-03 | 태그 전체 조회     | 삭제되지 않은 모든 태그 목록을 반환한다.                       |
| FR-TAG-04 | 태그 수정          | 이름 또는 색상을 수정한다. 전달된 필드만 반영한다.             |
| FR-TAG-05 | 태그 삭제          | 소프트 삭제한다. 조회 목록과 로그 상세 조인에서 모두 제외된다. |
| FR-TAG-06 | 로그에 태그 연결   | 로그에 태그를 붙인다.                                          |
| FR-TAG-07 | 로그에서 태그 해제 | 로그에서 태그 연결을 제거한다.                                 |

## 6. 비즈니스 규칙

| ID        | 규칙                                                                                                                           |
| --------- | ------------------------------------------------------------------------------------------------------------------------------ |
| BR-TAG-01 | 태그 이름은 저장 전 정규화된다(공백 정리 등).                                                                                  |
| BR-TAG-02 | 이름은 전역에서 유일하다. 활성 상태의 동일 이름 태그가 있으면 생성 시 오류를 반환한다.                                         |
| BR-TAG-03 | 삭제된 태그와 같은 이름으로 생성하면 새 레코드를 만들지 않고 기존 레코드를 복구한다. 이때 새로 전달된 색상이 적용된다.         |
| BR-TAG-04 | 로그 하나에 연결 가능한 태그 수는 최대 **5개**다.                                                                              |
| BR-TAG-05 | 이미 연결된 태그를 중복 연결할 수 없다.                                                                                        |
| BR-TAG-06 | 태그 이름의 최대 길이는 **20자**로 정의되어 있다.                                                                              |
| BR-TAG-07 | 태그 기본 색상은 `gray`다.                                                                                                     |
| BR-TAG-08 | 태그를 삭제해도 `task_tag` 연결 레코드는 남아 있으나, 조회 시 삭제된 태그가 조인에서 제외되므로 로그 화면에는 표시되지 않는다. |
| BR-TAG-09 | 로그가 삭제되면 해당 로그의 태그 연결도 함께 삭제된다(CASCADE).                                                                |

## 7. 화면 및 인터랙션

태그 섹션은 로그 카드(`TaskCard`)와 로그 상세 패널(`RightPanel`) 양쪽에 나타난다.

- 헤더: `Tags` 라벨 + `n/5 used` 카운터
- 트리거: 연결된 태그 칩 목록. 각 칩에 제거 버튼이 있다. 연결된 태그가 없으면 `Add Tag` 칩을 표시한다.
- 드롭다운(`TagSelector`)
  - 상단: 검색 입력 (`Search tags...`)
  - 하단: 전체 태그 목록. 선택 시 연결, 재선택 시 해제
  - 목록 내에서 태그를 새로 만들거나, 이름·색상을 수정하거나, 삭제할 수 있다
- 연결/해제는 낙관적 업데이트로 즉시 반영되며, 실패 시 롤백 후 오류 토스트를 표시한다.

## 8. 예외 및 오류 처리

| 상황                                  | 처리                                    |
| ------------------------------------- | --------------------------------------- |
| 중복 이름으로 생성                    | `Tag with name "<이름>" already exists` |
| 존재하지 않는 태그 수정               | `Tag not found or no changes made`      |
| 존재하지 않거나 이미 삭제된 태그 삭제 | `Tag not found`                         |
| 태그 5개 초과 연결                    | `A task can have a maximum of 5 tags`   |
| 중복 연결                             | `Tag already associated with the task`  |

모든 오류는 전역 뮤테이션 오류 처리기를 통해 사용자 친화적 문구로 변환되어 토스트로 표시된다.

## 9. 인터페이스 (IPC 채널)

| 채널             | 인자                      | 반환            |
| ---------------- | ------------------------- | --------------- |
| `tag.create`     | `{ name, color? }`        | 태그            |
| `tag.get`        | `id`                      | 태그 또는 빈 값 |
| `tag.getAll`     | —                         | 태그 목록       |
| `tag.update`     | `id`, `{ name?, color? }` | 태그            |
| `tag.softDelete` | `id`                      | —               |
| `task.addTag`    | `taskId`, `tagId`         | 로그 상세       |
| `task.removeTag` | `taskId`, `tagId`         | 로그 상세       |

## 10. 현재 제한사항 및 향후 계획

- 태그 이름 최대 길이(20자)는 상수로 정의되어 있으나 저장소 계층에서 강제 검증하지 않는다.
- 태그 기준으로 로그를 필터링하는 기능이 없다(`TaskFilterParams`에 태그 필터가 없음).
- 주간 요약 분석의 그룹 기준에 태그가 포함되지 않는다(프로젝트/작업 유형/세부 유형만 지원).
- 태그 사용 횟수, 미사용 태그 정리 같은 관리 기능이 없다.
- `tag_created`, `tag_deleted` 분석 이벤트 상수는 정의되어 있으나 전송되지 않는다.
