# 로그(Task) 관리 기능 정의서

## 1. 개요

illog의 최소 기록 단위인 **로그(Task)** 를 생성·조회·수정·삭제하는 기능입니다. 로그는 프로젝트, 작업 유형/세부 유형, 태그, 시작·종료 시각, 노트, AI 회고를 묶는 중심 엔티티입니다.

## 2. 목적 및 사용자 가치

- 하루에 수행한 작업을 부담 없이 한 줄로 기록한다.
- 기록에 분류(프로젝트/유형/태그)와 소요 시간을 덧붙여 이후 주간·프로젝트 단위 분석의 재료로 삼는다.

## 3. 용어 정의

| 용어         | 정의                                                                      |
| ------------ | ------------------------------------------------------------------------- |
| 로그(Task)   | 사용자가 기록하는 단일 작업 항목                                          |
| 상태(Status) | `todo` / `in_progress` / `done` 세 가지                                   |
| 소프트 삭제  | 레코드를 물리적으로 지우지 않고 `deletedAt`을 채워 조회에서 제외하는 방식 |

## 4. 데이터 모델

테이블 `task` (`src/main/database/schema/task.ts`)

| 컬럼              | 타입               | 제약 / 기본값                                    |
| ----------------- | ------------------ | ------------------------------------------------ |
| `id`              | text               | PK, UUID 자동 생성                               |
| `title`           | text               | NOT NULL, 기본값 `'Untitled'`                    |
| `description`     | text               | NULL 허용                                        |
| `status`          | text enum          | `todo` \| `in_progress` \| `done`, 기본값 `todo` |
| `project_id`      | text               | `project.id` FK, `ON DELETE CASCADE`             |
| `task_type_id`    | text               | `task_type.id` FK, `ON DELETE SET NULL`          |
| `task_subtype_id` | text               | `task_subtype.id` FK, `ON DELETE SET NULL`       |
| `started_at`      | integer(timestamp) | NOT NULL, 기본값 현재 시각                       |
| `end_time`        | integer(timestamp) | NULL 허용                                        |
| `created_at`      | integer(timestamp) | NOT NULL, 기본값 현재 시각                       |
| `updated_at`      | integer(timestamp) | NOT NULL, 갱신 시 자동 변경                      |
| `done_at`         | integer(timestamp) | 완료 처리 시각                                   |
| `deleted_at`      | integer(timestamp) | 소프트 삭제 시각                                 |

인덱스: `status`, `deleted_at`, `(status, deleted_at)`, `created_at`, `started_at`, `task_type_id`, `task_subtype_id`

연관: `task_tag`(N:M 태그), `task_note`(1:1), `task_reflection`(1:1), `project`(N:1), `task_type`/`task_subtype`(N:1)

## 5. 기능 상세

| ID         | 기능      | 설명                                                                                                                                |
| ---------- | --------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| FR-TASK-01 | 로그 생성 | 입력값 없이 빈 로그를 생성한다. 제목 `Untitled`, 상태 `todo`, 시작 시각은 생성 시점. 생성 직후 태그·프로젝트·유형은 모두 비어 있다. |
| FR-TASK-02 | 단건 조회 | ID로 로그를 조회한다. 삭제된 로그는 조회되지 않으며 없으면 오류를 반환한다.                                                         |
| FR-TASK-03 | 상세 조회 | ID로 태그 목록·프로젝트·작업 유형·세부 유형을 함께 조회한다. 삭제된 연관 항목은 결과에서 제외된다.                                  |
| FR-TASK-04 | 목록 조회 | 필터 조건에 맞는 로그 목록을 연관 정보와 함께 조회한다. 정렬은 생성일 내림차순 고정.                                                |
| FR-TASK-05 | 로그 수정 | 제목, 설명, 상태, 프로젝트, 작업 유형, 세부 유형, 시작/종료 시각을 수정한다. 전달된 필드만 반영한다(부분 수정).                     |
| FR-TASK-06 | 태그 연결 | 로그에 태그를 연결한다.                                                                                                             |
| FR-TASK-07 | 태그 해제 | 로그에서 태그 연결을 제거한다.                                                                                                      |
| FR-TASK-08 | 로그 삭제 | 소프트 삭제한다. 이후 모든 조회에서 제외된다.                                                                                       |

### 5.1 목록 필터 규칙 (FR-TASK-04)

| 필터        | 동작                                                                                        |
| ----------- | ------------------------------------------------------------------------------------------- |
| `status`    | 해당 상태와 일치하는 로그만                                                                 |
| `projectId` | 해당 프로젝트 소속 로그만                                                                   |
| `startTime` | 종료 시각이 기준 이후이거나, 종료 시각이 없고 시작 시각이 기준 이후인 로그 (구간 겹침 포함) |
| `endTime`   | 시작 시각이 기준 이전인 로그                                                                |
| `search`    | 제목 또는 설명에 부분 일치                                                                  |

- 시간 필터는 ISO 8601 문자열을 받는다.
- `startTime`/`endTime`을 함께 주면 **해당 구간과 겹치는** 로그가 모두 포함된다(구간에 완전히 포함될 필요 없음).
- 삭제되지 않은 로그만 대상이다.

## 6. 비즈니스 규칙

| ID         | 규칙                                                                                                   |
| ---------- | ------------------------------------------------------------------------------------------------------ |
| BR-TASK-01 | 상태를 `done`으로 바꾸면 완료 시각(`done_at`)이 현재 시각으로 기록된다.                                |
| BR-TASK-02 | 상태를 `done` 이외로 되돌리면 완료 시각이 `null`로 초기화된다.                                         |
| BR-TASK-03 | 작업 유형을 변경하면서 세부 유형을 함께 지정하지 않으면 기존 세부 유형은 `null`로 초기화된다.          |
| BR-TASK-04 | 세부 유형을 지정할 때 해당 세부 유형이 대상 작업 유형에 속하지 않으면 오류를 반환하고 수정을 거부한다. |
| BR-TASK-05 | 로그 하나에 연결 가능한 태그는 최대 **5개**이며, 초과 시 오류를 반환한다.                              |
| BR-TASK-06 | 이미 연결된 태그를 다시 연결하려 하면 오류를 반환한다.                                                 |
| BR-TASK-07 | 이미 삭제된 로그를 다시 삭제하면 "찾을 수 없음" 오류를 반환한다.                                       |
| BR-TASK-08 | 삭제는 소프트 삭제만 제공하며, 사용자에게 복구 수단은 제공하지 않는다.                                 |

## 7. 화면 및 인터랙션

### 7.1 로그 카드 (`TaskCard`)

Today / History / 프로젝트 인사이트 화면에서 공통으로 사용된다.

- 상단: 상태 선택기(드롭다운), 시작·종료 시간 선택기 + 소요 시간 표기
- 중단: 프로젝트 배지 선택기, 작업 유형/세부 유형 배지 선택기
- 본문: 제목·설명 인라인 입력 (1초 디바운스 자동 저장)
- 하단: 태그 선택기 (`n/5 used` 카운터)
- 카드 클릭 → 우측 상세 패널 열림. 단, 링크·입력·버튼·셀렉터 등 인터랙티브 요소를 클릭한 경우에는 열리지 않는다.
- 우클릭 컨텍스트 메뉴: `Open Note`, `Delete`
- `Delete` 선택 시 "Delete this log?" 확인 다이얼로그를 거친다.

### 7.2 상세 패널 (`RightPanel`)

우측에서 슬라이드로 열리는 720px 폭 패널. 상태, 프로젝트/유형, 제목·설명, 마지막 수정 시각, 태그, 시간, 노트 에디터, AI 회고 영역을 포함한다. 로그를 전환하면 스크롤이 최상단으로 초기화된다.

### 7.3 낙관적 업데이트

수정·삭제·태그 연결/해제·프로젝트/유형 지정은 모두 **낙관적 업데이트**로 처리된다. 요청 전에 화면 캐시(오늘 목록 / 전체 목록 / 상세)를 먼저 갱신하고, 실패하면 이전 상태로 롤백한 뒤 오류 토스트를 표시한다.

## 8. 예외 및 오류 처리

| 상황                              | 처리                                                              |
| --------------------------------- | ----------------------------------------------------------------- |
| 존재하지 않거나 삭제된 로그 조회  | `NOT_FOUND` — "The requested item could not be found."            |
| 수정 대상이 없거나 변경 사항 없음 | 오류 반환 후 낙관적 업데이트 롤백                                 |
| 태그 5개 초과 / 중복 연결         | 오류 반환, 토스트 표시                                            |
| 세부 유형-유형 불일치             | `VALIDATION_ERROR` — "Invalid input. Please check and try again." |

## 10. 현재 제한사항 및 향후 계획

- 하드 삭제, 휴지통, 복구 UI가 없다.
- 정렬 기준을 사용자가 바꿀 수 없다(생성일 내림차순 고정).
- 반복 로그, 하위 로그, 우선순위, 마감일 개념이 없다.
- `taskTypeId` / `taskSubtypeId` 필터는 타입 정의(`TaskFilterParams`)에는 존재하지만 저장소 조회 로직에는 아직 반영되어 있지 않다.
- 검색 필터는 화면에 노출되지 않는다(API 레벨에서만 사용 가능).
