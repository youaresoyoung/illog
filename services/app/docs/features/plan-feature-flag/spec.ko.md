# 플랜 / 기능 플래그 기능 정의서

## 1. 개요

사용자 **플랜(요금제)** 에 따라 특정 기능의 사용 가능 여부를 결정하는 게이팅 체계입니다. 현재는 인증이 없어 모든 사용자가 로컬 플랜이며, 유료 기능은 전부 비활성 상태입니다.

## 2. 목적 및 사용자 가치

- 유료 기능과 무료 기능의 경계를 코드 한 곳에서 관리한다.
- 인증·결제 도입 이전에도 기능 게이팅 구조를 미리 갖춰 둔다.
- 사용 불가한 기능이 왜 잠겨 있는지(필요 플랜)를 사용자에게 안내한다.

## 3. 용어 정의

| 용어                      | 정의                                               |
| ------------------------- | -------------------------------------------------- |
| 플랜(Plan)                | 사용자 요금제 등급                                 |
| 기능 플래그(Feature Flag) | 특정 기능의 활성 여부와 필요 플랜 정보를 담은 항목 |
| 프로필(Profile)           | 사용자 식별자와 플랜을 담은 정보                   |

## 4. 데이터 모델

데이터베이스 테이블이 아니라 **메모리 내 상수**로 정의되어 있다(`UserService`).

### 4.1 플랜

| 플랜         | 설명                  | 현재 사용 여부           |
| ------------ | --------------------- | ------------------------ |
| `local`      | 인증 없는 로컬 사용자 | **현재 유일하게 사용됨** |
| `free`       | 향후 무료 가입 사용자 | 미사용 (자리 표시)       |
| `pro`        | 향후 유료 사용자      | 미사용                   |
| `enterprise` | 향후 기업 사용자      | 미사용                   |

### 4.2 기능

| 기능 ID             | 설명                        | 필요 플랜 | 구현 상태              |
| ------------------- | --------------------------- | --------- | ---------------------- |
| `ai.reflection`     | 로그 노트 기반 AI 회고 생성 | `pro`     | 구현됨 (API 키 미설정) |
| `ai.weekly-summary` | AI 주간 요약                | `pro`     | 미구현                 |
| `ai.suggestion`     | AI 제안                     | `pro`     | 미구현                 |
| `sync.cloud`        | 클라우드 동기화             | `pro`     | 미구현                 |
| `export.pdf`        | PDF 내보내기                | `pro`     | 미구현                 |

### 4.3 플랜별 활성 기능

| 플랜         | 활성 기능                      |
| ------------ | ------------------------------ |
| `local`      | 없음                           |
| `free`       | 없음                           |
| `pro`        | 전체 5개                       |
| `enterprise` | 전체 5개 (현재는 `pro`와 동일) |

### 4.4 현재 프로필

| 항목      | 값                  |
| --------- | ------------------- |
| 사용자 ID | `local-user` (고정) |
| 플랜      | `local` (고정)      |

## 5. 기능 상세

| ID         | 기능                | 설명                                                           |
| ---------- | ------------------- | -------------------------------------------------------------- |
| FR-PLAN-01 | 현재 프로필 조회    | 사용자 ID와 플랜을 반환한다.                                   |
| FR-PLAN-02 | 플랜 정보 조회      | 프로필과 전체 기능 플래그 목록을 함께 반환한다.                |
| FR-PLAN-03 | 기능 활성 여부 확인 | 특정 기능이 현재 플랜에서 사용 가능한지 반환한다.              |
| FR-PLAN-04 | 화면 단위 게이팅    | 기능이 비활성이면 관련 UI를 비활성화하고 필요 플랜을 안내한다. |
| FR-PLAN-05 | 서버 단위 게이팅    | 메인 프로세스에서도 기능 활성 여부를 재검증한다.               |

## 6. 비즈니스 규칙

| ID         | 규칙                                                                                    |
| ---------- | --------------------------------------------------------------------------------------- |
| BR-PLAN-01 | 현재 모든 사용자는 `local` 플랜이며 유료 기능은 전부 비활성이다.                        |
| BR-PLAN-02 | 기능 플래그 목록은 전체 기능을 항상 포함하며, 각 항목이 활성 여부와 필요 플랜을 담는다. |
| BR-PLAN-03 | 필요 플랜은 5개 기능 모두 `pro`로 정의되어 있다.                                        |
| BR-PLAN-04 | 화면 게이팅만으로 신뢰하지 않고, 실제 기능 실행 지점(메인 프로세스)에서도 검증한다.     |
| BR-PLAN-05 | 플랜 정보를 불러오지 못한 상태에서는 모든 기능을 비활성으로 간주한다(기본 거부).        |
| BR-PLAN-06 | 비활성 기능 관련 오류는 재시도하지 않는다.                                              |

## 7. 렌더러 사용 방식

| 훅                            | 반환                                    | 용도                |
| ----------------------------- | --------------------------------------- | ------------------- |
| `useFeatureFlag(featureId)`   | `{ enabled, requiredPlan, isLoading }`  | 단일 기능 게이팅    |
| `useFeatureFlags(featureIds)` | `{ flags, isLoading }`                  | 여러 기능 동시 확인 |
| `useCurrentPlan()`            | `{ plan, isLocal, profile, isLoading }` | 현재 플랜 확인      |

전역 사용자 스토어(`useUserStore`)에도 플랜이 캐시되어 있어 동기적 접근이 필요한 경우 사용한다. 다만 **신뢰할 수 있는 출처는 조회 결과**이며, 스토어는 보조 캐시다.

### 7.1 게이팅 UI 예시

AI 회고 버튼은 기능이 비활성이면 다음과 같이 표시된다.

```
활성:   [ Ask AI Reflection ]
생성 중: [ Generating... ]            (비활성)
비활성: [ AI Reflection (PRO plan required) ]  (비활성)
```

## 11. 현재 제한사항 및 향후 계획

- **인증 체계가 없어 플랜을 실제로 변경할 수 없다.** 프로필은 항상 `local-user` / `local`로 고정 반환된다.
- 플랜 정보가 데이터베이스나 원격 설정이 아닌 코드 상수로 하드코딩되어 있다.
- 5개 기능 중 `ai.reflection`만 구현되어 있으며, 나머지 4개는 플래그만 존재한다.
- 유료 플랜으로 업그레이드하는 경로(결제·안내 화면)가 없다.
- 코드 주석에 따르면 향후 인증 도입 시 원격 설정 서비스에서 플랜별 활성 기능을 내려받고, 사용자 프로필을 데이터베이스에 저장하는 방향이 계획되어 있다.
