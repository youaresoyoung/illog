illog — 아키텍처 다이어그램

Electron 데스크톱 앱 services/app의 소스 코드를 직접 읽고 분석해 그린 다이어그램입니다. 프로세스 간 관계 → Main 프로세스 내부 계층 → Renderer 컴포넌트 트리 → 상태 흐름 순서로, 범위를 좁혀가며 살펴볼 수 있도록 구성했습니다.

1 시스템 아키텍처 개요

Electron의 세 프로세스(Renderer / Preload / Main)가 어떻게 연결되는지와, Renderer가 사용하는 워크스페이스 패키지(@illog/ui 등)를 보여줍니다. Renderer는 window.api(Preload가 contextBridge로 노출)를 통해서만 Main과 통신하며, 다크모드 전환처럼 Main → Renderer 방향으로 흐르는 상태(점선)도 존재합니다.

2 Main 프로세스 내부 의존성

3 Renderer 컴포넌트 의존성

main.tsx → App.tsx부터 실제 라우팅(createHashRouter)과 페이지·섹션 컴포넌트, 그리고 각 페이지가 사용하는 데이터 훅(hooks/queries/*)까지 실제 import 관계를 따라간 결과입니다. 모든 서버 데이터 훅은 결국 Preload가 노출한 window.api 하나로 수렴합니다.

4 상태 흐름도

illog 렌더러는 세 종류의 상태를 함께 씁니다: Zustand 스토어(클라이언트 UI 상태), React Context(테마처럼 프로세스 경계를 넘거나, 에디터 툴바처럼 인스턴스별로 스코프된 상태), React Query 캐시(SQLite에서 온 서버 상태). 스타디움 도형은 Zustand 스토어, 육각형은 Context, 실린더는 React Query 캐시입니다.
