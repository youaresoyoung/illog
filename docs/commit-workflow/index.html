illog 커밋 작성 프로세스

AI 커밋 메시지 생성부터 husky 훅 검증까지, 로컬에서 커밋 하나가 완성되는 전체 과정

1전체 흐름 개요

코드 수정 후 git add로 스테이징하고, 선택적으로 pnpm gen:commit(codeqa CLI)이 Groq LLM을 호출해 커밋 메시지 초안을 생성합니다. git commit 실행 시 husky가 등록한 두 개의 훅(pre-commit → commit-msg)이 순서대로 실행되어 코드 스타일과 커밋 메시지 포맷을 검증합니다.

2AI 커밋 메시지 생성 상세 (pnpm gen:commit)

packages/codeqa/src/cli.ts가 --commit 플래그를 받아 commit.ts의 generateCommitMessage()를 호출합니다. 스테이징된 diff를 Groq Chat Completions API에 스트리밍 요청으로 보내고, husky commit-msg 훅이 강제하는 포맷 규칙을 시스템 프롬프트에 명시해 그 형식에 맞는 메시지를 생성합니다.

3pre-commit 훅 상세 (lint-staged)

.husky/pre-commit은 pnpm pre-commit만 실행하며, 이는 루트 package.json의 lint-staged 설정을 따릅니다. 파일 확장자 패턴별로 다른 도구가 스테이징된 파일에만 적용되고, 수정된 결과는 자동으로 재스테이징됩니다.

4commit-msg 훅 상세 (포맷 검증)

.husky/commit-msg는 커밋 메시지 파일 (.git/COMMIT_EDITMSG)을 읽어 4가지 정규식 패턴 중 하나라도 일치하는지 순서대로 검사합니다. 하나도 일치하지 않으면 허용 포맷 가이드를 출력하고 exit 1로 커밋을 거부합니다.

5왜 commitlint 대신 직접 만든 셸 스크립트인가

이 저장소에는 commitlint가 전혀 설치되어 있지 않습니다 — .husky/commit-msg가 grep -Eq로 4개의 정규식을 직접 매칭하는 방식으로 같은 역할을 대신합니다. 둘 다 "hook 시점에 메시지를 검증한다"는 목적은 같고, commitlint 역시 결국 같은 commit-msg 훅 안에서 npx commitlint --edit $1로 호출되는 구조이므로, 실제 비교 대상은 "hook이냐 아니냐"가 아니라 "직접 짠 스크립트냐 commitlint를 끼워 넣은 스크립트냐"입니다.

핵심 이유: 이 프로젝트는 Conventional Commits, PR 브래킷 형식 ([#123] feat: ...), Gitmoji, WIP/Merge 특수 패턴까지 4갈래를 모두 허용하는 관대한 규칙을 씁니다. Gitmoji와 PR 브래킷 형식은 commitlint의 기본 config-conventional 스펙 밖의 규칙이라 어차피 커스텀 플러그인을 작성해야 했을 것이고, 그럴 바엔 정규식 4줄을 직접 짜는 편이 의존성 추가 없이 더 빠르고 이 프로젝트 특유의 예외 케이스를 자유롭게 넣기 쉬웠을 것으로 보입니다.
이 프로젝트: 직접 짠 셸 스크립트 commitlint
구현 방식 bash grep -Eq로 정규식 4개 순차 매칭 @commitlint/cli + @commitlint/config-conventional 등 설정 기반 파서
유연성 패턴 추가/수정은 셸 스크립트를 직접 편집 commitlint.config.js에서 type 목록, scope 필수 여부, 대소문자, 줄 길이 등을 선언적으로 설정
파싱 정확도 정규식 기반이라 body/footer, BREAKING CHANGE 같은 스펙 세부 요소는 검사하지 않음 conventional-commits 스펙을 제대로 파싱 (header/body/footer 분리, ! breaking change 등)
이 프로젝트의 예외 규칙 Gitmoji, PR 브래킷 형식([#123] feat: ...), WIP/Merge를 정규식에 자유롭게 추가 — 실제로 이미 반영됨 기본 스펙 밖의 규칙이라 별도 커스텀 룰/플러그인을 작성해야 함
의존성 외부 패키지 불필요, husky만 있으면 동작 commitlint 관련 devDependency 필요
에러 메시지 스크립트에 하드코딩된 안내문 (이모지 + 예시로 커스터마이징됨) 어떤 규칙을 어겼는지 자동 리포트 (예: subject-case, type-empty)
